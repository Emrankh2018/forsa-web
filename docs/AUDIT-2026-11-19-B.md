# Audit and review B — the website ready for the VPS (2026-11-19, Asia/Qatar)

Scope: roadmap 2 (`../../production/ROADMAP-VPS-READY.md`) as built in commits `7da547a` and `276c7c0`, the whole front end it touches, the standalone server the VPS will run, and the live site https://forsa-demo.vercel.app (deployment `dpl_DBYr8yJY615k3PirMtVd2fPiFCw5`, commit `276c7c0`). Done by Claude Opus 5.5 in the owner's session: the builder checking its own work, not an independent review. No database, server or VPS work (none exists yet).

## TL;DR

**Ready for the VPS, as far as the website can be without the server.** Every roadmap step is done and live. The site builds into a standalone Node server that passed the full browser suite (714 passed, 0 failed, three times). The audit found **one defect that would have broken the launch**: after go-live, `robots.txt` would have told search engines to skip `/projects`, `/partners`, `/privacy` and `/trainers`, because its rules matched by prefix. It is fixed and unit-tested, and live. Two smaller issues (duplicate cache headers in the Nginx file; CI testing a different server from the one the VPS runs) are fixed too. The pages also got lighter: the Arabic home page sends about 100 KB less script and its HTML is 21% smaller, and its Lighthouse performance went from 90 to 93–94 (blocking time 270 → 140–180 ms). The full browser suite also passes on the live site (714 passed, 0 failed). Limits: the Nginx and systemd files can't be run on this Windows machine, so they get their first real test on the VPS (`nginx -t`). Real sign-in, saving and email still wait for the VPS work.

## Findings

| # | Severity | Finding | State |
|---|---|---|---|
| 1 | **High at launch** | `robots.txt` (production branch) disallowed `/ar/p`, `/ar/trainer` and the like as prefixes. Crawlers match prefixes, so at go-live this would have blocked `/ar/projects`, `/ar/partners`, `/ar/privacy` and `/ar/trainers` (and the English twins), hiding the main public pages from search. Not visible today, because everything is blocked before launch | **Fixed** (`276c7c0`): exact rules (`/ar/trainer$` and `/ar/trainer/`) built in `packages/shared/src/paths.ts`, with a crawler-style matcher and tests that the private areas are blocked and 16 public pages that share prefixes are not. Live |
| 2 | Medium (VPS) | `deploy/nginx/forsa.conf` added a second `Cache-Control` on top of Next's own for built files and icons (two headers, conflicting) | **Fixed**: built files keep Next's `immutable` header; icons replace Next's `max-age=0` with one day |
| 3 | Medium (process) | CI ran the browser suite on `next start`, which Next warns against with standalone output, so CI tested a different server from the VPS's | **Fixed**: CI sets `E2E_STANDALONE=1`; the test server listens on IPv4 and IPv6 so `localhost` works on Linux runners |
| 4 | Medium (process) | CI passed in about 19 minutes against a 20-minute limit: the next few tests would have failed CI on time alone | **Fixed**: limit raised to 30 minutes |
| 4b | Low | The site's `Strict-Transport-Security` (one year, no subdomains) replaces Vercel's longer default on `forsa-demo.vercel.app`. Harmless (`vercel.app` is preloaded in browsers anyway); on the VPS this header is what protects the domain | Accepted. When the domain is final and every subdomain is on HTTPS, consider `includeSubDomains` |
| 5 | Low | CSP allows inline scripts (`'unsafe-inline'`): Next's own page data is inline, and nonces would force every page to render per request (Next.js docs). The policy still blocks scripts from other sites, plug-ins, framing and off-site form posts | Accepted by design; revisit if pages become dynamic anyway after sign-in |
| 6 | Low (speed) | The largest single download is the Amiri display font's Arabic file (about 100 KB, preloaded on every page). It is a design choice | Open, owner's call (a lighter display face or a self-made subset). Not changed |
| 7 | Info | Nginx and systemd files are written from the official docs and read through, but can't be run here (Windows, no Nginx) | Run `sudo nginx -t` and `systemctl status forsa-web` on the VPS (`docs/VPS-DEPLOY.md`) |
| 8 | Info | Earlier audit notes for the VPS still stand: every server function must check the session and role first; strip line breaks from names in email subjects | Carried to the VPS work (`docs/AUDIT-2026-11-19.md` findings 4 and 5) |
