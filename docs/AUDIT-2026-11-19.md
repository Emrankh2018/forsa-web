# Audit, review and test — front end before the VPS (2026-11-19, Asia/Qatar)

Scope: everything in `platform/forsa-web` at commit `dd93385` (roadmap steps 1–7) and the live site https://forsa-demo.vercel.app. Done by Claude Opus 5.5 in one session (a self-review, not an independent one). No database, server or VPS work; nothing deployed.

## TL;DR

**Ready with minor issues (after the one fix below ships).** All checks pass and every page and journey in the suite works on the live site, with one real defect: **five kinds of address inside the signed-in areas answered "500 server error" instead of "page not found"** when the item did not exist (for example `/ar/me/projects/anything`). The cause is found and fixed locally, with a test that proves it (fails on live, passes on the fix). **Shipped the same day** (commit `cf34bdd`, deployment `dpl_8Lq6h4q5CyDooQRgSZBs6RVL3Awo`, `forsa-demo.vercel.app` re-pointed); on live the five addresses now answer 404 and 606 browser tests pass. Nothing else blocks; the remaining items are for go-live or the VPS work.

## Findings

| # | Severity | Finding | State |
|---|---|---|---|
| 1 | **High** (visible to anyone, live) | `/me/projects/<unknown>`, `/me/learning/courses/<course>/<unknown lesson>`, `/org/projects/<unknown>`, `/org/projects/<project>/review/<unknown>`, `/trainer/workshops/<unknown>/edit` answered **500** with the error page instead of 404. Vercel log: *"Page changed from static to dynamic at runtime, reason: headers"*. Cause: page metadata called `getTranslations('…')` without the language, so next-intl read the request headers, which a statically built route may not do at request time. | **Fixed locally**: new `apps/web/lib/locale-param.ts` (`localeOf(params)`); all 22 metadata functions that translate now pass the language (as next-intl's docs require). Regression test `e2e/app.spec.ts` "answers 404, not 500" (5 addresses × 2 languages × 3 widths): **failed on the old live site (500), passes on the fix**. **Live since commit `cf34bdd`**: 264 area and not-found tests plus 342 public-site tests passed on live after the re-point |
| 2 | Medium (before go-live) | No `Content-Security-Policy` header. The only inline script is the arrival gate (fixed text), so a policy with a hash or nonce is straightforward. | Open, recommend at go-live |
| 3 | Low (go-live) | `/robots.txt`, `/sitemap.xml` and `/favicon.ico` answer 404. Harmless today (every page sends `noindex`; the icon is `icon.svg`), but search engines and older browsers need them at go-live. | Open |
| 4 | Low (VPS) | `lib/data/writes.ts`: none of the 49 server functions checks who is signed in yet. Correct for now: they save nothing and no screen imports them, so they are not reachable. When wired on the VPS: (a) each must check the session and role first (the contract already says so); (b) `deleteAccount(input, word)` takes the confirmation word from the caller, so the server should work it out from the language itself; (c) `saveSwitches` accepts any object, so it must keep relying on the database refusing the payments flag (it does: `set_setting`). | Note for the VPS step |
| 5 | Low (VPS) | Email templates escape every value in the HTML (correct). The subject line is filled unescaped, which is right for a subject, but line breaks in names should be removed before sending so a name cannot add mail headers. | Note for the email-sending step |
| 6 | Low | `/test` (tester kit): if the browser refuses clipboard access, "copy" fails silently, and notes are lost on reload. | Open, small |
| 7 | Process | The link crawl only follows links that exist, so it could not catch finding 1; the new test covers unknown items. The full suite takes about 16 minutes against live, and running it alongside a build exhausts this machine's memory. Run them one after the other. | Noted |
